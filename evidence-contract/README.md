# Directed Evidence-contract evaluation

Seven preselected controls across 86 frozen validation cases exercised VFA's production checkers on isolated copies of retained attempt state. In the selected run, 22 inputs were accepted, 63 malformed inputs were rejected, and one valid-coordinate input exposed a semantic gap. All 86 outcomes matched the frozen expected outcomes. An earlier harness run raised two setup exceptions before the VFA checker was called; the [amendment record](amendments.md) preserves that deviation. These outcomes do not measure vulnerability-detection accuracy or exploit behavior.

Read the [protocol](protocol.md), [amendments](amendments.md), [case matrix](evidence-contract-cases.csv), [filtered results](evidence-contract-results.csv), and [fixture summary](evidence-contract-fixture-summary.csv). [Protocol provenance](protocol-freeze.json) records the freeze time and hashes of the retained original inputs. [Result provenance](results-provenance.json) records the selected run and the hashes of private and public records. Public test IDs use the `EC-` prefix; the private frozen records use a different prefix, with the same route and sequence suffixes.

The original checker runner is not distributed as a standalone reproducer because it requires historical attempt state, target bytes, Evidence blobs, grants, and the corresponding VFA code. The filtered public matrix and results permit inspection of the tests and outcomes, not full replay. The repository-level `verify_dossier.py` checks published file integrity only; it does not repeat the checker experiment.
